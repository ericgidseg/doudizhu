# 斗地主 · 内网对战

零依赖 Node.js 实现的三人斗地主，**无需 npm install、无需外网**，专为公司内网环境设计。

---

## 一、运行教程

### 1. 启动服务端

```bash
cd doudizhu
node server.js          # 默认端口 8000
node server.js 9000     # 指定其它端口
```

启动后控制台会打印可访问地址：

```
斗地主服务端已启动 (零依赖)
  本机访问:   http://localhost:8000
  主机名访问: http://YahahadeMac-mini.local:8000   <- 内部 DNS 可解析
  内网IP访问: http://192.168.5.25:8000             <- 发给同事直接玩
```

### 2. 部署方式（三选一）

| 方式 | 适用 | 操作 |
|---|---|---|
| **分发给同事** | 同事 Mac (Apple Silicon) | `./build-app.sh` → 产出 `dist/斗地主.app` + `.zip`，发给同事解压双击即用，**无需装 Node** |
| 跑在自己电脑 | 同网段/同 WiFi 同事 | 直接 `node server.js`，把上面打印的 IP/主机名地址发群里 |
| 公共内网服务器 | 全公司 / 跨网段 | 把 `doudizhu/` 目录拷到一台大家都能 ping 通的服务器，跑 `node server.js` |

要求：Node.js ≥ 16（推荐 18+），无其它依赖。

#### .app 分发说明
- `./build-app.sh` 生成 `dist/斗地主.app`（58MB）和 `dist/斗地主.app.zip`（18MB）
- 目前只支持 **Apple Silicon Mac**（arm64）；Intel Mac 或 Windows 需要在那台机器上跑 `node server.js` 或另行打包
- 同事首次打开会被 Gatekeeper 拦：右键 .app → **打开** → 再点 **打开**，之后正常双击
- .app 启动后 replays 持久化在 `~/Library/Application Support/doudizhu/replays/`

### 3. 同事加入

- 同事浏览器打开你发的地址（如 `http://192.168.5.25:8000`），输入昵称。
- 大厅下方会列出 **可加入的房间**，点一下直接进；也可手动输入 4 位房间号。
- 凑齐 3 人后，**房主**点「开始游戏」。

### 4. 连不上时排查

- macOS 防火墙：系统设置 → 网络 → 防火墙，允许 node 或放行该端口。
- AP/客户端隔离：访客 WiFi、隔离网段的同事连不到你 → 改用公共服务器部署。
- 公司 EDR/安全软件拦入站连接 → 同上，上服务器。

## 二、游戏规则

### 配置
- 3 人，一副 54 张牌（含大王小王），每人 17 张，留 3 张底牌。
- 地主 1 人 vs 农民 2 人（农民是队友），先出完手牌的一方获胜。

### 流程
1. **叫地主**：轮流叫分（不叫/1/2/3），最高者成地主并拿 3 张底牌、先出牌；全不叫重新发牌。
2. **出牌**：必须出同牌型且更大的牌，或用炸弹/王炸；也可「不出」。两家连续不出，最后出牌者重新领出。
3. **结束**：任一方出完即胜，倍数结算，支持「再来一局」。

### 牌的大小
大王 > 小王 > 2 > A > K > Q > J > 10 > 9 > 8 > 7 > 6 > 5 > 4 > 3（不分花色）

### 牌型
| 牌型 | 说明 |
|---|---|
| 单张 | 任意一张 |
| 对子 | 两张同点（大小王不算对） |
| 三张 | 三张同点 |
| 三带一 / 三带二 | 三张 + 1 单 / + 1 对 |
| 顺子 | ≥5 张连续单牌（如 34567，不含 2 和王） |
| 连对 | ≥3 对连续对子（如 334455，不含 2 和王） |
| 飞机 | ≥2 组连续三张，可带同数单牌或对子（如 555666+34 / +3344） |
| 四带二 | 四张 + 2 单 或 + 2 对（不算炸弹） |
| 炸弹 💥 | 四张同点，压一切普通牌型，倍数 ×2 |
| 王炸 🚀 | 大王+小王，最大，倍数 ×2 |

### 操作
- 点选手牌 →「出牌」；「提示」自动选最小能压的牌；「不出」跳过。
- 右下角发消息/快捷短语；左上角显示底牌与倍数。

### AI 难度
单人模式可选四档 AI（房主也可在房间内随时切换）：

| 难度 | 特点 |
|---|---|
| 普通 | 最小压牌，偶尔放水，适合上手 |
| 困难 | 残局抢出、记剩牌、给队友喂牌、炸弹不轻易浪费 |
| 大师 | 全局规划：开局对整手牌做最少手数分解（顺子/连对/飞机/三带最优组合），出牌按规划执行；全程记牌判断"我这手是不是全场最大"；给残局队友精确喂牌，地主临门必压；炸弹只在能收尾或地主将赢时用 |
| 传说 | 蒙特卡洛模拟：每个候选出牌抽样若干种对手暗牌分布，把整局 rollout 到结束，按实际胜率选牌 |

### 对局复盘
每局结束自动录制到 `replays/` 目录（保留最近 100 局）。大厅底部点「📼 对局复盘」或直接访问 `/replay.html`：

- 列出所有录制对局（房间号 / 玩家 / 难度 / 结果 / 步数）
- 点进任意一局：**三家手牌全部亮出**，步进/滑杆/空格播放回放
- 左键点日志任意一行直接跳转到那一步，看 AI 当时剩什么牌、为什么这么出

也可直接读 JSON：`replays/r<房号>-<局号>.json` 里有 `players[].hand`（初始手牌）、`actions[]`（逐步叫分/出牌/pass）、`bottom`、`landlordSeat`、`winnerSeat` 等完整信息，方便脚本化分析。

## 三、技术说明

| 文件 | 说明 |
|---|---|
| `server.js` | HTTP 静态服务 + 房间/叫分/出牌状态机，服务端权威校验 |
| `ws.js` | 手写极简 WebSocket 实现（RFC6455），零依赖 |
| `cards.js` | 牌型判定 / 比较 / 提示算法 |
| `public/` | 纯 HTML/CSS/JS 客户端（原生 WebSocket，无框架无 CDN） |

完全离线：拷目录走 U 盘或内部仓库即可运行。
